# ЕГЭ 2027 — локальный учебный центр

React + TypeScript + Vite, версия 0.2.0. Stage 2 добавляет полный офлайн-комплект, установку PWA и резервные копии прогресса. Учебный материал и спокойный интерфейс перенесены из существующего личного учебного центра; новые темы и задания на этом этапе не добавлялись.

## Запуск

Требуется современный Chromium и совместимый с Vite Node.js. Проверено на Node.js 24.19.0, pnpm 11.25.0 и Microsoft Edge. Все зависимости зафиксированы в `pnpm-lock.yaml`; новые пакеты для PWA не добавлялись.

```text
pnpm install --frozen-lockfile --ignore-scripts
pnpm dev
```

Разработка доступна по http://127.0.0.1:5173/. В этом режиме Service Worker намеренно отключён, поэтому это не адрес для проверки офлайн-установки.

Для сборки и проверки PWA:

```text
pnpm exec tsc --noEmit
pnpm test
pnpm exec vite build --emptyOutDir false
pnpm preview
```

Готовая версия доступна по http://127.0.0.1:4173/. Обычный `pnpm build` также выполняет проверку TypeScript и сборку; в проверках использован вариант без очистки прежних build-артефактов. Они не включаются в новый офлайн-комплект.

Открывать `index.html` двойным щелчком через `file://` нельзя: приложение должно сначала загрузиться через HTTP на localhost или через HTTPS. Локальный сервер нужен для первой загрузки и доставки обновлений; после подготовки комплекта приложение работает при недоступном сервере.

Для Android нужен согласованный отдельно HTTPS-адрес со статической сборкой. Хостинг на этом этапе не выбран, приложение никуда не публиковалось.

## Структура

- `src/components` — общий интерфейс, мини-тесты, тренажёры и резервные копии.
- `src/pages` — главная, предмет, тема, ошибки, повторение, прогресс, настройки и короткие занятия.
- `src/domain` — типы, проверка ответов, статистика, строгая проверка резервных копий.
- `src/data` — статический учебный комплект и каталог с постоянными идентификаторами.
- `src/storage` — IndexedDB и атомарная замена прогресса при импорте.
- `src/state` — состояние приложения и очередь сохранения.
- `src/pwa` — регистрация Service Worker, проверка готовности, обновления и установка.
- `src/styles` — стили эталона и мобильные дополнения.
- `public` — manifest, SVG и PNG-иконки, включая maskable.
- `scripts` — механизм предварительного кэширования для сборки Vite и шаблон Service Worker.
- `work/tests` — автоматические тесты и браузерные проверочные сценарии.
- `outputs` — локальные отчёты, снимки и тестовые JSON; в Git не входят.
- `dist` — готовая сборка; в Git не входит.

## Учебный комплект

67 тем, 19 готовых объяснений, 67 исходных вопросов: 57 обычных и 10 лёгких. Также сохранены существующие практические тренажёры и три предложения для синтаксического разбора. 48 тем остаются страницами плана без выдуманного содержания. Python-код представлен текстом, исполнение кода не добавлено.

`src/data/reference.json` содержит источник, дату извлечения и SHA-256. Материалы восстановлены из синтаксического дерева без исполнения исходного JavaScript. Объяснения — дерево разрешённых тегов с текстом, без `dangerouslySetInnerHTML`.

Перенесённые вопросы сохраняют `origin: custom`, `sourceType: training`, ссылку на эталон. Принадлежность ФИПИ не предполагается. Модель допускает `official`, `generated`, `reconstructed`, `custom`, тему, подтему, сложность, источник, год, тип задания и будущие связи `requires` / `related`.

## Полный офлайн и обновления

Vite автоматически формирует список всех ресурсов текущей сборки и файлов `public`. Весь банк и объяснения входят в локальный JavaScript-пакет. Service Worker предварительно сохраняет весь комплект, включая ещё не открытые темы; это не кэш только посещённых страниц.

При первой загрузке дождись сообщения в «Данные и настройки»: «Полный учебный комплект сохранён». Если ресурс отсутствует или его SHA-256 не соответствует сборке, установка этой версии отклоняется. Готовность проверяется у активного Service Worker, включая идентификатор сборки HTML. При отсутствии места нельзя объявлять комплект готовым.

Каждая сборка использует отдельный кэш. Учебные запросы обслуживаются из полного кэша активной версии, без подмешивания ресурсов другой версии. Новая версия заранее загружается, затем ждёт закрытия всех вкладок и окон приложения. После следующего открытия активируется целиком. Принудительный `skipWaiting` не используется. Неудачное обновление оставляет прежнюю готовую версию.

Для будущего размещения нужно доставлять HTML, Service Worker и остальные файлы одной согласованной сборки. Не изменяй байты ресурсов средствами хостинга после сборки: встроенные хеши проверяют именно готовые файлы. HTML и `sw.js` должны перепроверяться, без длительного неизменяемого HTTP-кэша. Пути относительные; работа под подпапкой проверена.

Нет обязательных внешних шрифтов, CDN, API или сервера данных. Внешние ссылки на источники в настройках требуют сети, но не участвуют в занятиях. Нейтральный индикатор «Офлайн» использует состояние сети браузера, а не доступность конкретного сайта.

## Прогресс и резервные копии

Существующая IndexedDB сохранена: база `ege-local-center`, версия 1, хранилище `progress`, ключ `current`. Пользовательский документ имеет `schemaVersion: 1`; учебный банк в базу не записывается. Обновления Service Worker не открывают и не очищают IndexedDB.

Попытки, ошибки, заметки, повторения, история и настройки сохраняются последовательно и атомарно. Исторические снимки вопросов в ошибках остаются доступными после изменения встроенного банка. Неверный формат ответа не создаёт попытку. Ошибкой считается распознанный, но неверный ответ; правильный ответ не удаляет прошлую ошибку.

В настройках доступны экспорт и импорт JSON. Формат резервной копии:

```text
format: ege-progress-backup
backupVersion: 1
appVersion: 0.2.0
createdAt: ISO timestamp
data: пользовательский StudyState с schemaVersion: 1
```

Экспорт ждёт завершения очереди записи. JSON содержит пользовательскую историю и снимки ошибочных заданий, но не весь поставляемый учебный банк. Предельный размер файла — 20 МиБ. Неизвестные будущие версии отклоняются до добавления соответствующей миграции.

Импорт сначала проверяет размер, JSON, версии, типы, даты, перечисления, уникальность идентификаторов и связи записей. Повреждённый файл ничего не меняет. Перед заменой показываются состав файла, предупреждение и обязательное подтверждение. Данные полностью заменяются, а не объединяются.

Замена и отдельная копия прежнего прогресса записываются в одной транзакции. Копия хранится под уникальным ключом `before-import:<дата>:<UUID>`. При ошибке записи обе операции отменяются. Эти локальные копии доступны технически через IndexedDB; самостоятельный экран их восстановления на этом этапе не добавлялся. Для независимого восстановления используй экспортированный JSON вне данных браузера.

Прогресс привязан к origin браузера, включая протокол, имя хоста и порт. `localhost`, `127.0.0.1`, 5173 и 4173 имеют отдельные сохранения. Перенос между адресами выполняется через экспорт/импорт. Перед импортом закрой остальные окна приложения. Одновременное редактирование прогресса несколькими окнами не объединяется.

## Проверки

`pnpm test`: 18 тестов правил прогресса, формата ответов, резервных копий и Service Worker. TypeScript и production build проходят.

Дополнительные сценарии запускаются отдельно в изолированном профиле Edge. Они используют уже доступный Playwright; это проверочный инструмент, не зависимость приложения. Первым аргументом передаётся папка `node_modules` инструмента, содержащая Playwright:

```text
node work/tests/browser-checks.mjs <playwright-node-modules> http://127.0.0.1:4180
node work/tests/update-checks.mjs <playwright-node-modules>
```

Для первого сценария предварительно запусти `pnpm preview --port 4180`. Второй создаёт свой временный localhost-сервер. Сценарии не используют пользовательский профиль и не удаляют созданные тестовые профили автоматически. Проверены полные офлайн-перезапуски браузера, все темы, сохранение IndexedDB, мобильная ширина, импорт/экспорт, ошибка транзакции и обновления в двух окнах. Подробные результаты — `outputs/STAGE-2-REPORT.md`.

## Проверка на настоящем Android

После согласованного HTTPS-размещения: установить в Chrome, дождаться готового комплекта, включить авиарежим, закрыть приложение и запустить с иконки. Открыть ранее не посещённый урок, ответить на вопросы, повторно запустить и проверить прогресс. Проверить системные загрузку и выбор JSON, восстановление, иконку и обновление после закрытия всех окон.

## Ограничения

Браузер может удалить локальное хранилище при очистке данных, нехватке места или использовании инкогнито. Экспорт — независимая защита от такой потери. Нет облака, аккаунтов, исполнения Python, оптимизации под iOS и совместного редактирования несколькими окнами. Некоторые отличия практических визуализаций от эталона, отмеченные в Stage 1, остались вне этого этапа. Новые учебные функции не добавлялись.
