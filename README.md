# ЕГЭ 2027 — локальный учебный центр

React + TypeScript + Vite, версия 0.3.2-dev (Stage 3B.1, локальная рабочая ветка). Stage 2 добавляет полный офлайн-комплект, установку PWA и резервные копии прогресса. Учебный материал и спокойный интерфейс перенесены из существующего личного учебного центра; Stage 3B.1 добавляет 100 оригинальных заданий и встроенную проверку программ.

## Запуск

Требуется современный Chromium и совместимый с Vite Node.js. Проверено на Node.js 24.19.0, pnpm 11.25.0 и Microsoft Edge. Все зависимости зафиксированы в `pnpm-lock.yaml`; новые пакеты для PWA не добавлялись.

```text
pnpm install --frozen-lockfile --ignore-scripts
pnpm dev
```

Разработка доступна по http://127.0.0.1:5173/. В этом режиме Service Worker намеренно отключён, поэтому это не адрес для проверки офлайн-установки.

Для сборки и проверки PWA:

```text
pnpm exec tsc --noEmit
pnpm test
pnpm exec vite build --emptyOutDir false
pnpm preview
```

Готовая версия доступна по http://127.0.0.1:4173/. Обычный `pnpm build` также выполняет проверку TypeScript и сборку; в проверках использован вариант без очистки прежних build-артефактов. Они не включаются в новый офлайн-комплект.

Открывать `index.html` двойным щелчком через `file://` нельзя: приложение должно сначала загрузиться через HTTP на localhost или через HTTPS. Локальный сервер нужен для первой загрузки и доставки обновлений; после подготовки комплекта приложение работает при недоступном сервере.

Стабильная Stage 2 размещена на https://radisonbe.github.io/ege-2027-offline/ и проверена на реальном Android/Samsung Internet. Её tag v0.2.0 указывает на commit 3206652 (приложение 0.2.1). Stage 3A находится только в локальной ветке stage-3-content-engine и не опубликована.

## Структура

- `src/components` — общий интерфейс, мини-тесты, тренажёры и резервные копии.
- `src/pages` — главная, предмет, тема, ошибки, повторение, прогресс, настройки и короткие занятия.
- `src/domain` — типы, проверка ответов, статистика, строгая проверка резервных копий.
- `src/data` — статический учебный комплект и каталог с постоянными идентификаторами.
- `src/storage` — IndexedDB и атомарная замена прогресса при импорте.
- `src/state` — состояние приложения и очередь сохранения.
- `src/pwa` — регистрация Service Worker, проверка готовности, обновления и установка.
- `src/styles` — стили эталона и мобильные дополнения.
- `public` — manifest, SVG и PNG-иконки, включая maskable.
- `scripts` — механизм предварительного кэширования для сборки Vite и шаблон Service Worker.
- `work/tests` — автоматические тесты и браузерные проверочные сценарии.
- `outputs` — локальные отчёты, снимки и тестовые JSON; в Git не входят.
- `dist` — готовая сборка; в Git не входит.

## Полный офлайн и обновления

Vite автоматически формирует список всех ресурсов текущей сборки и файлов `public`. Весь банк и объяснения входят в локальный JavaScript-пакет. Service Worker предварительно сохраняет весь комплект, включая ещё не открытые темы; это не кэш только посещённых страниц.

При первой загрузке дождись сообщения в «Данные и настройки»: «Полный учебный комплект сохранён». Если ресурс отсутствует или его SHA-256 не соответствует сборке, установка этой версии отклоняется. Готовность проверяется у активного Service Worker, включая идентификатор сборки HTML. При отсутствии места нельзя объявлять комплект готовым.

Каждая сборка использует отдельный кэш. Учебные запросы обслуживаются из полного кэша активной версии, без подмешивания ресурсов другой версии. Новая версия заранее загружается, затем ждёт закрытия всех вкладок и окон приложения. После следующего открытия активируется целиком. Принудительный `skipWaiting` не используется. Неудачное обновление оставляет прежнюю готовую версию.

Для будущего размещения нужно доставлять HTML, Service Worker и остальные файлы одной согласованной сборки. Не изменяй байты ресурсов средствами хостинга после сборки: встроенные хеши проверяют именно готовые файлы. HTML и `sw.js` должны перепроверяться, без длительного неизменяемого HTTP-кэша. Пути относительные; работа под подпапкой проверена.

Нет обязательных внешних шрифтов, CDN, API или сервера данных. Внешние ссылки на источники в настройках требуют сети, но не участвуют в занятиях. Нейтральный индикатор «Офлайн» использует состояние сети браузера, а не доступность конкретного сайта.

## Прогресс и резервные копии

Существующая IndexedDB сохранена: база `ege-local-center`, версия 1, хранилище `progress`, ключ `current`. Пользовательский документ имеет `schemaVersion: 2`; v1 мигрируется атомарно с сохранением оригинала. Встроенный банк хранится отдельно; в прогрессе имеются исторические снимки заданий. Обновления Service Worker не открывают и не очищают IndexedDB.

Попытки, ошибки, заметки, повторения, история и настройки сохраняются последовательно и атомарно. Исторические снимки вопросов в ошибках остаются доступными после изменения встроенного банка. Неверный формат ответа не создаёт попытку. Ошибкой считается распознанный, но неверный ответ; правильный ответ не удаляет прошлую ошибку.

В настройках доступны экспорт и импорт JSON. Формат резервной копии:

```text
format: ege-progress-backup
backupVersion: 2
appVersion: 0.3.2-dev
createdAt: ISO timestamp
data: пользовательский StudyState с schemaVersion: 2
```

Экспорт ждёт завершения очереди записи. JSON содержит пользовательскую историю и снимки ошибочных заданий, но не весь поставляемый учебный банк. Предельный размер файла — 20 МиБ. Неизвестные будущие версии отклоняются до добавления соответствующей миграции.

Импорт сначала проверяет размер, JSON, версии, типы, даты, перечисления, уникальность идентификаторов и связи записей. Повреждённый файл ничего не меняет. Перед заменой показываются состав файла, предупреждение и обязательное подтверждение. Данные полностью заменяются, а не объединяются.

Замена и отдельная копия прежнего прогресса записываются в одной транзакции. Копия хранится под уникальным ключом `before-import:<дата>:<UUID>`. При ошибке записи обе операции отменяются. Эти локальные копии доступны технически через IndexedDB; самостоятельный экран их восстановления на этом этапе не добавлялся. Для независимого восстановления используй экспортированный JSON вне данных браузера.

Прогресс привязан к origin браузера, включая протокол, имя хоста и порт. `localhost`, `127.0.0.1`, 5173 и 4173 имеют отдельные сохранения. Перенос между адресами выполняется через экспорт/импорт. Перед импортом закрой остальные окна приложения. Одновременное редактирование прогресса несколькими окнами не объединяется.

## GitHub Pages

Подготовлен workflow `.github/workflows/pages.yml` для `Radisonbe/ege-2027-offline`. Он запускается после push в `main` или вручную через Actions → Deploy PWA to GitHub Pages → Run workflow (ветка main). В другом репозитории или ветке deployment не выполняется.

Сначала пользователь должен разрешить публикацию и включить Settings → Pages → Build and deployment → Source: GitHub Actions в репозитории. Workflow не создаёт репозиторий и не включает Pages самостоятельно. На GitHub Free для Pages нужен публичный репозиторий; при подходящем платном тарифе возможен приватный исходный репозиторий, но это само по себе не закрывает доступ к сайту. Отдельный PAT или npm-токен не нужен: используются штатные права GITHUB_TOKEN и OIDC для deployment.

### Что сделать после разрешения на публикацию

1. Создать пустой репозиторий `Radisonbe/ege-2027-offline` (для Free — Public), без добавления другого README или .gitignore.
2. Выбрать Source: GitHub Actions в Settings → Pages. Убедиться, что официальные Actions разрешены политиками репозитория.
3. Включить HTTPS, если этот переключатель доступен; собственный домен не требуется.
4. Закоммитить подготовленные workflow и README локально, затем передать исходники и конфигурацию из этого Git-репозитория в ветку main нового репозитория. Использовать Git push, а не загрузку всей локальной папки через веб-интерфейс. Сам push запустит автоматическую публикацию, поэтому делать его только после согласования.
5. Дождаться успешных build и deploy в Actions. Если Pages включены уже после первого push, вручную запустить workflow на main.
6. Открыть `https://radisonbe.github.io/ege-2027-offline/` с завершающим `/`.

Workflow использует Node.js 24 и pnpm 11.25.0, устанавливает зависимости по lock-файлу с отключёнными lifecycle-скриптами, выполняет TypeScript и тесты, проверку происхождения `audit:public`, затем production build. При неуспешной проверке deployment не запускается. Официальные Actions закреплены на конкретных commit SHA; новые зависимости приложения не добавлены. Сборка выполняется в новом checkout runner, поэтому старые локальные бандлы в dist в публикацию не попадут.

### Что публикуется

На Pages передаётся только `dist`: index.html, один JS-бандл и CSS, icon.svg, три PNG-иконки, manifest.webmanifest, sw.js, offline-inventory.json и THIRD_PARTY_NOTICES.txt. Текущая сборка содержит 11 файлов. Jekyll не используется: публикация идёт через готовый Pages artifact; .nojekyll не требуется.

Исходники, конфигурация, тестовые сценарии и workflow будут находиться в Git-репозитории, но не в статическом Pages artifact. node_modules, work-профили, локальные кэши, резервные рабочие копии, exports прогресса и outputs исключены .gitignore. Установка зависимостей происходит только в CI runner и не включает их в сайт.

### Пути и пользовательские данные

`base: './'` сохраняется. Для этой установки manifest и Service Worker находятся под `/ege-2027-offline/`; manifest id и scope разрешаются в эту подпапку, start_url — `/ege-2027-offline/#home`. Ресурсы загружаются относительно того же адреса, без привязки к 127.0.0.1 или порту. Hash-навигация не требует отдельных серверных маршрутов для тем.

IndexedDB остаётся `ege-local-center`, версия 1. Обновление GitHub Pages не удаляет её: новая полная версия Service Worker ждёт закрытия всех окон, а старый прогресс хранится отдельно. Отсутствующий или изменённый файл новой сборки не проходит проверку SHA-256 и не подменяет предыдущий полный комплект.

Для следующих выпусков используй тот же production URL и не очищай данные сайта. При переходе с localhost или workers.dev на github.io браузер создаёт отдельное хранилище; прежний прогресс переносится через экспорт/импорт JSON. Самостоятельной облачной синхронизации нет. IndexedDB на одном origin github.io общая для путей, поэтому другие копии этого приложения на том же домене не являются независимыми профилями.

### Android после публикации

1. В Chrome открыть production URL, перейти в «Данные и настройки», дождаться сообщения «Полный учебный комплект сохранён» и установить приложение через кнопку или меню Chrome.
2. Включить авиарежим, полностью закрыть окна, запустить PWA с иконки. Открыть заполненную тему, которую раньше не посещали, и страницу плана.
3. Ответить на несколько вопросов, открыть подсказку и решение, сохранить заметку. Перезапустить PWA и проверить попытки, ошибки, заметки и статистику.
4. Проверить экспорт и импорт JSON через системный выбор файлов Android.
5. Вернуть сеть. После следующего push и успешной публикации проверить уведомление о новой версии, закрыть все окна приложения, снова открыть и убедиться в сохранении прогресса. Не удалять PWA и данные сайта для обычного обновления.

Локальные проверки подтверждают работу этой точной подпапки, полный офлайн-комплект и сохранение IndexedDB при обновлении. Доставка GitHub Pages и установка Android/Samsung Internet подтверждены для Stage 2. Workflow успешно выполнялся для её публикаций. # Python Playground — Stage 3A.1

В разделе Python доступна локальная песочница: textarea, отступы, stdin, stdout/traceback, остановка и лимит выполнения. Pyodide 314.0.7 запускает CPython 3.14.2. Сетевые обращения из песочницы запрещены CSP и runtime-политикой. Код хранится отдельно в ege-python-playground/drafts/current, schema 1. Прогресс schema 2 и backup v2 сохранены; старые Stage 2/Stage 3A backup импортируются. Backup прогресса не включает Python-черновик: его нужно копировать отдельно перед очисткой данных сайта.

Интерактивный input() использует JSPI при наличии; иначе доступны заранее заполненные строки stdin. Выполнение ограничено 10 секундами, ожидание ввода — 2 минутами, вывод — 65 536 символами. Остановка/timeout уничтожают Worker и восстанавливают чистый runtime. Это учебная песочница; жёсткого лимита потребления RAM нет, ОС-модули/пакеты отсутствуют либо ограничены.

Модель PythonTask поддерживает predict-output/write-program/complete-code/fix-bug/write-function и тестовые метаданные. Ожидаемые результаты не передаются Worker; сравнение выполняется вне него. На публичном клиенте hidden tests не могут быть секретом от владельца браузера — это основа учебной проверки, а не защищённая экзаменационная система.

`node scripts/check-offline-build.mjs <build-directory>` проверяет окончательные SHA-256, SW и наличие всех пяти runtime-файлов. Inventory теперь создаётся по финальным записанным файлам, после обработки lazy imports Vite. CI выполняет эту проверку после build.

Проверки: 58 unit-тестов, 30 сценариев песочницы и 29 прежних браузерных сценариев. Песочница проверяется через work/tests/playground-browser-checks.mjs с путями bundled-node-modules, новой сборки и стабильной Stage 3A сборки. Все профили/черновики/измерения остаются в ignored work/outputs. Реальная клавиатура и поведение Samsung Android требуют отдельного теста владельцем после согласованной публикации.

## Stage 3B.1 — задания с программированием

100 новых вопросов в отдельных пакетах stage3b1-*.json: по 25 на предмет. В Python 20 задач с кодом, в информатике 5; остальные — предметные ответы, выбор одного/нескольких вариантов и чтение кода. Все origin generated, нумерация ЕГЭ не присваивается. Добавлены 12 базовых модулей и четыре дополнения к существующим объяснениям. Таксономия: 55 подтем, 95 навыков; исходные ID/тексты не меняются.

CodeExercise лениво использует тот же PythonRunner и runtime: запуск не оценивается, проверка запускает несколько изолированных входов/вызовов функции. Ожидания остаются вне Worker. Синтаксис, остановка и лимит времени не оцениваются; неверный результат/ошибка выполнения при проверке создаёт одну ошибку и максимум одну коррекцию в пределах задания, дня и режима либо шага Adaptive Review.

codeDrafts[questionId] — необязательное дополнение пользовательского документа schema 2, собственная схема черновика 1. Код/ввод сохраняются вместе с прогрессом и попадают в backup v2. Старые Stage 2/3A/3A.1 backup импортируются; старый backup без черновиков заменяет и черновики после явного предупреждения. Обратный импорт нового формата данных в старую версию приложения не обещается. Отдельная песочница по-прежнему имеет отдельную базу и не входит в progress backup.

Новые ежедневные подборки используют уникальные ID и честно сокращаются при малом банке. Исторические сессии с повторами продолжают загружаться. Подробности и ручной Android-checklist: docs/STAGE3B1.md. Локальная ветка не публикуется без отдельного согласования.
