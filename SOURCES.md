# Источники и правила публикации

Аудит: 2026-10-08. Реестр проверенных файлов: sources/publication.json. Он содержит источник, основание и SHA-256 (текст нормализован к LF для одинаковой проверки Windows/Linux). После изменения учебного материала требуется повторная проверка, а не автоматическое обновление хешей.

## Обязательная политика

Публичная версия и Git-репозиторий не содержат материалов третьих лиц без явного разрешения на перепубликацию. По умолчанию разрешены собственные материалы, оригинальные сгенерированные задания и материалы с явно совместимой лицензией и соблюдением её условий.

«Решу ЕГЭ», сторонние сборники и учебные сайты допускаются только как референсы тем, сложности и формата. Их тексты, объяснения, изображения, подборки и решения не копируются в публичный банк.

Доступность ФИПИ в открытом банке не является разрешением на массовую перепубликацию. Сохранять источник и ссылку; точное воспроизведение допускается только после отдельного подтверждения допустимости. Ссылки на ФИПИ в настройках — ссылки для самостоятельного ознакомления, а не загрузка заданий.

origin (official/generated/reconstructed/custom) описывает происхождение, но не выдаёт права. generated и reconstructed никогда не маркируются как official. Непроверенные материалы имеют clearance: unverified, блокируют публичную сборку и требуют решения владельца. Их нельзя молча удалять или объявлять собственными.

## Как добавлять будущий публичный материал

Для каждой партии/задания записать: постоянные ID, subject/topic/subtopic, origin, source URL, sourceYear/sourceType/examTaskType, автора/правообладателя, точную лицензию или основание разрешения, требования атрибуции, дату проверки, проверенные файлы и хеши. Нельзя подменять source ссылкой на агрегатор или делать вывод о правах только по доступности файла. Публичная проверка не заменяет ручной анализ нового материала.

## Личные локальные пакеты

Формат JSON: format = ege-private-learning-package; packageVersion = 1; id/title/source; topics (id/subject/title); lessons (topic/title/paragraphs); questions (существующая модель Question). Для хранения всегда добавляются distribution = private-import и importedAt. Метка происхождения оригинала сохраняется отдельно в Question.origin; это не делает пакет публичным или официальным банком приложения.

API: src/storage/private-packages.ts — importPrivatePackage(json), loadPrivatePackages(). База ege-private-learning-packages, версия 1, store packages; отделена от ege-local-center/progress. Импорт валидируется до записи; дубликат ID отклоняется, транзакция атомарна. Пакеты не объединяются со статическим каталогом, не включаются в резервную копию прогресса и не передаются по сети. Нет исполнения кода, внешних загрузок, HTML/SVG-ресурсов: урок содержит только инертные текстовые абзацы. Максимум 20 МиБ. Правомерность личного использования пользователь проверяет отдельно; local/private не является лицензией.

Сейчас добавлена основа API и хранения. Кнопка импорта/просмотр личных пакетов в интерфейс не добавлены; подключение этих экранов — отдельный этап. Это предотвращает случайное смешивание с нынешним учебным банком.

Исходные личные файлы размещать только в private-packages/, personal-materials/, local-data/, user-data/, imports/ или backups/ (также во вложенных каталогах), либо с суффиксом .private-package.json / .private-progress.json. Эти пути исключены .gitignore. Экспорты ege-progress-*.json / ege-backup-*.json тоже исключены. Не класть личные файлы в src/public, не использовать git add -f и не прикладывать к Issues/Actions artifacts.

Vite дополнительно отклоняет личные директории в src/public и JSON-пакеты/резервные копии при сборке даже под другим именем. Проверка audit:public проверяет источник, хеши и запрещённые пути в текущем Git и истории. Work, outputs, node_modules, dist, профили и временные файлы остаются вне Git; Pages получает только dist из CI.

## Статус публикации

Публикация, remote, push и автоматический commit не выполнялись. Перед публикацией требуется отдельное подтверждение владельца. Проверка происхождения не должна включать пустой LICENSE на весь комплект и выдавать MIT React за лицензию на учебные материалы. Лицензия собственного проекта пока не назначена; она не обязательна для размещения личного публичного сайта и выбирается отдельно, если владелец захочет дать права на повторное использование.
