## Мои темы / Быстрая практика

- Предметы и знакомые/отрабатываемые темы выбираются вручную. Начальные
  отметки берутся из личных статусов; ready не считается освоением.
- 10/20/30, смешанная базовая/средняя; сложные только по явному выбору. Приоритет незнакомых ID.
- requires и предварительные навыки проверяются через стабильные ID.
- Только явно распределённая практика; контрольные ID не раскрываются.
- Новые ID сначала; семейства, тема и подтема по возможности чередуются.
  Seed задаёт воспроизводимый порядок, сам выбранный порядок сохранён.
- Повторы требуют включения флажка. Исчерпание/нехватка показаны честно.
- Одно задание, можно пропускать/возвращаться/выйти/завершить без штрафа.
- Сохраняются фильтры, порядок, показанные задачи, черновой ответ,
  тренировочные ответы и код через существующий CodeExercise/Runner.
- Попытки обычной практики, контроля и повторений учитываются для
  определения встреченных ID; контрольные результаты не пересчитываются.
- Статус «Уверенно» автоматически не устанавливается. Как раньше,
  первый тренировочный ответ может перевести «Не изучено» в «Изучаю».
- На странице темы добавлен переход к подборке её новых вопросов.
  Старые интерактивные тренажёры сохранены; короткая сессия использует
  practice allocation вместо раскрытия зарезервированных контрольных ID.

pooled snapshots `id@version`, compact sessions и ссылки на training.

## Финальные уточнения поведения

- Новые прогнозы Python имеют answerFormat=python-output: сохраняются
  границы значений и регистр; многострочный краткий ответ вводится через
  пробел. `31` не равно `3 1`. Реальный stdout не меняется. Старые text-
  вопросы и математический parseNumber сохранены без изменений.
- Готовый код открывается по явному запросу после проверки или при наличии
  прежней проверки того же ID/version. Подсказки практики доступны раньше,
  экспериментальный Run сам по себе не открывает готовое решение.
- Запоздалый ответ/черновой ввод привязан к key исходного вопроса: после
  пропуска он не может стать ответом следующего. Worker проверяется
  реальным бесконечным циклом и отменой через переход.
- Snapshot reference должен быть собственным ключом pool. `toString` и
  `hasOwnProperty` не принимаются за снимок; повреждённый импорт отклоняется
  до подтверждения и не заменяет прежнее хранилище.
- Четыре explicit alias связывают старые приёмы корней/логарифмов с
  новыми вариантами; metadata старых вопросов не изменялась.
