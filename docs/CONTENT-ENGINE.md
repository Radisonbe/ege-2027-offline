# Content Engine — Stage 3A

## Данные

`src/data/banks/*.json` — встроенные пакеты. Формат: `schemaVersion: 1`, устойчивый `id` пакета, `subject`, массив `questions`. Каталог автоматически находит JSON-пакеты через eager glob Vite: для добавления пакета компоненты интерфейса менять не нужно. Все пакеты включаются при сборке, поэтому первый офлайн-запуск не зависит от посещённых страниц.

Каноническое задание содержит `id`, `subject`, `topic`, `subtopic`, `skills`, `difficulty`, `origin`, `source`, `sourceYear`, `sourceType`, `examTaskType`, `answerType`, `prompt`, `answer`, `hint`, `explanation`, `solution`, `principle`, `version`, `requires`, `related`, `remediates`; `options`, `wrongAnswers`, `easy` используются при необходимости. Неизвестные год/номер экзамена остаются null. Legacy-снимки вопросов без новых полей поддерживаются в прогрессе. ID и тексты нынешних 67 вопросов сохранены; никаких новых вопросов не добавлено.

`src/data/taxonomy.json`: 34 подтемы и 58 навыков. Предметы имеют прежние ID math/russian/informatics/python; темы — прежние 67 ID. Подтема относится к одной теме, навык — к одной теме/подтеме. Например: math → percent → percent.sub.inverse → percent.skill.original-price. Связи requires/related/remediates используют ID тем/навыков, не названия. Начальные зависимости немногочисленны; визуального графа нет. Оценка easy/medium — начальная педагогическая классификация, не официальный уровень экзамена.

`reference.json` остаётся неизменной записью переноса эталона для объяснений, плана, интерактивных примеров и проверки точности. Его старые questions/python не включаются повторно в клиентский банк: используются именованные импорты нужных разделов. Сам рабочий банк находится в четырёх новых пакетах.

## Проверка пакетов

`pnpm run check:content` проверяет версии, обязательные поля, уникальные ID, topic/subtopic/skill, принадлежность предмету, корректный ответ, варианты, связи и циклы requires. Проверка встроена в build/build:public, Vite plugin и будущий workflow Pages. Некорректный пакет блокирует сборку. Runtime-загрузчик изолирует испорченный пакет, не добавляет его записи и сообщает диагностику; остальные пакеты, оболочка и прогресс сохраняют работоспособность. Некорректная общая таксономия также не уничтожает прогресс.

Новый пакет требует записи в `sources/publication.json` с явным clearance, основанием и SHA-256; после изменения существующего — повторного аудита. Для generated-пакета нельзя незаметно сменить origin на official или private-import. Официальный или reconstructed материал требует лицензионного/явного разрешения, а не заявления о собственной генерации. Все текущие 67 вопросов — generated.

Личные пакеты остаются в отдельной IndexedDB `ege-private-learning-packages`. Не входят в встроенный каталог, автоматическое повторение этого этапа, Git, сборку или сеть. Модель и метаданные поддерживают private-import; UI личных пакетов не добавлялся.

## Подбор

`selectReview` получает состояние, банк, навыки, размер (5/10/15/20; default 15), фильтр и дату. Сначала отбираются изученные темы. Явный статус «Не изучено» исключает тему; исторические ответы используются только если записи статуса нет. Зависимости проверяются по уже изученным темам необходимых навыков, включая цепочку prerequisites. Новые темы не включаются для исправления пробелов: базовое повторение выбирается только из доступного материала.

Базовый балл — сумма объяснимых факторов:

| Фактор | Баллы |
|---|---:|
| Последний ответ неверный, ошибка за 7 дней / более старая | +28 / +10 |
| Независимые ошибки в теме за 7 дней | +9 за наблюдение, до +18 |
| Не показывалось в изученной теме / давно не показывалось | +12 / до +30 |
| Подошло повторение | +10 и до +10 за просрочку |
| Нужна практика / Повторить / Изучаю / Уверенно | +22 / +20 / +8 / +4 |
| Тема изучена в последние 7 дней | +8 |
| Эмпирическая неуверенность | 0…+10 |
| Сложность соответствует уверенности / не соответствует | +8 / −8 |
| Базовый навык для шага с повторными ошибками | +12 |
| Требуемый базовый навык пока слаб | −12 |
| Показывалось сегодня | −30 |
| Частота показов за 7 дней | −12 за показ, до −48 |

Уверенность оценивается по независимым первым ответам: `(верных + 1) / (наблюдений + 2)`. Без истории используется умеренная оценка, для вручную уверенной темы — 0.8. Это эвристика, не модель прогнозирования балла ЕГЭ. Позднейшая корректная попытка снимает непосредственный бонус последней ошибки, но не удаляет историю.

Не разобранные вручную добавленные ошибки также учитываются, если у них нет соответствующей попытки. Связанная с попыткой запись банка ошибок не считается второй ошибкой. Такие записи повышают приоритет уже изученной темы, но сами по себе не открывают неизученную тему.

При последовательном выборе добавляется штраф: −80 за появление этого ID в занятии, −12 за уже выбранную тему, −18 за навык, −8 за подтему; дополнительно −100 для того же вопроса подряд, −12 для той же темы подряд и −35 для того же навыка подряд. До повторов используются все подходящие уникальные ID. При равенстве используется лексикографический ID. Случайности и AI API нет. История заранее индексируется по вопросам, темам, навыкам и показам.

Если банк меньше запрошенного размера, сохраняется выбранное количество 5/10/15/20 с разнесёнными повторами; UI предупреждает об этом. Для пустого набора занятие не начинается. Внутри занятия подборка фиксируется со снимками вопросов и причинами баллов, чтобы перезапуск/новый банк не меняли уже начатую работу.

## Фиксированный пример

`work/tests/adaptive.test.mjs` задаёт ошибки p2 30 сентября и 5 октября, верный f1 1 августа, изученные percent/functions/binary, дату 8 октября и просроченные повторения. Выбираются **e4 → p3 → f1 → b2 → p2**. e4 получает **88**: ошибки темы 9 + ещё не показывалось 12 + срок повторения 20 + нужна практика 22 + неуверенность 5 + соответствие сложности 8 + базовый навык 12. Старое ошибочное p2 возвращается, но не вытесняет основу и уверенные темы. JSON с полным расчётом генерируется в outputs/STAGE3A-PRIORITY-EXAMPLE.json; точный порядок проверяется unit-тестом.

## Прогресс и миграция

Физическая IndexedDB `ege-local-center`, версия 1, store progress/current сохранена. Документ — schemaVersion 2. Добавлено `adaptive.sessions` и `adaptive.exposures`. Новые попытки сохраняют subject/subtopic/skills и sessionId для автоматического занятия. Экспозиция фиксируется при фактическом открытии шага, один раз на слот. Для ответов вне этого режима и истории Stage 2 используется дата попытки: старых несуществующих показов миграция не выдумывает.

`contentVersion` содержит устойчивый отпечаток рабочего банка и таксономии. Это информационная версия для истории, а не криптографическая проверка. Проверки происхождения файлов и ресурсов Service Worker по-прежнему используют SHA-256.

Миграция v1 → v2 сначала строго проверяет весь документ, сохраняет точный оригинал под `before-migration:1-2:<timestamp>:<uuid>` и записывает новый документ в одной транзакции. При ошибке обе записи отменяются. Попытки, ошибки, снимки, заметки, статусы, история и интервалы не изменяются; ID не переименовываются. При загрузке v2 повторная миграция не выполняется.

Backup v2 содержит schemaVersion 2 и журнал занятий/показов со снимками. Старый backup v1 автоматически мигрируется при импорте. Неизвестные будущие версии и испорченные ссылки отклоняются до замены. Сохранилось подтверждение полной замены и транзакционная копия before-import. Новые данные v2 не предназначены для чтения старым приложением Stage 2: для отката нужны старый backup v1 или сохранённая копия до миграции.

## Результаты и слабые места

Итог считает первые ответы, отдельно показывает исправленные после повтора. Разбивка — по предметам, темам, навыкам. «Стоит повторить» различает единичную ошибку и несколько независимых ошибок. Слабость требует минимум двух ошибочных наблюдений и доли ошибок ≥40% среди последних 12 наблюдений. Повторы одного ID и исправления внутри одной сессии — одно наблюдение; для Stage 2 одинаковый ID в один день группируется консервативно. Это не диагноз и не автоматическая смена «Уверенно».

После завершения полностью верного повторения темы, у которой подошёл срок, исходный интервал растёт один раз в день по прежней шкале 1/3/7/14/30. Ошибка сохраняет прежнее правило возврата к одному дню; правильный ответ после ошибки не стирает ошибку и не увеличивает сброшенный интервал.

История начатых и завершённых занятий сохраняется; можно продолжить после закрытия или открыть прошлый итог. Интерфейс показывает последний десяток записей, хранилище сохраняет остальные. Условия многовкладочного редактирования Stage 2 не изменены: одновременное независимое редактирование прогресса не объединяется.
