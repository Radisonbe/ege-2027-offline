# Python Playground — архитектура Stage 3A.1

## Runtime и offline

Pyodide 314.0.7 (CPython 3.14.2) поставляется неизменённым в public/python-runtime/314.0.7: pyodide.mjs, pyodide.asm.mjs, pyodide.asm.wasm, python_stdlib.zip, pyodide-lock.json. Npm-архив проверен по integrity; менеджер пакетов не запускался. Пакеты NumPy/pandas/scipy/micropip не поставляются. Доступны встроенные math/json/random/itertools/statistics и стандартные конструкции Python; ОС, threading, multiprocessing, sockets, ssl/pydoc/zoneinfo имеют ограничения upstream.

Все 29 ресурсов (включая ленивый экран, runtime и лицензии) устанавливаются SW заранее с проверкой SHA-256. Ready означает полный комплект. Обновление ждёт закрытия всех окон, IndexedDB не очищается. writeBundle читает финальные файлы, потому что Vite может изменить lazy-import/preload-код после generateBundle. check-offline-build проверяет фактический artifact после завершения build и запускается в workflow.

## Изоляция и протокол

PythonRunner создаёт скрытый iframe srcdoc с sandbox=allow-scripts без allow-same-origin. Его origin непрозрачный. Фрейм создаёт отдельный классический Worker из Blob; loader/factory-модули, wasm и stdlib получены родителем из локального комплекта и переданы как данные. Pyodide createPyodideModule явно подключён: стандартная автоматическая загрузка модуля для classic Worker в этой версии не подходит. Версия закреплена; изменение loader требует повторной проверки.

CSP фрейма разрешает только собственный скрипт/Blob и WASM-eval, Worker/Blob; connect только Blob. Основное приложение не ослабляет CSP. После bootstrap fetch отключён. jsglobals — пустой объект; единственный узкий зарегистрированный модуль предоставляет ввод. Никаких ссылок на DOM, React state или пользовательские базы в Worker нет. В тесте даже рефлексия JS остаётся внутри origin null и не получает IndexedDB приложения.

Родитель принимает события только от своего frame.contentWindow: ready, stdout, stderr, traceback, input, return, done, load-error, stopped. Вывод ограничен, сообщения активного запуска проверяются по run ID. Это защита учебного приложения, не абсолютная песочница для враждебного кода или ограничитель памяти браузерного процесса.

## Вывод, ошибки, ввод

setStdout/setStderr используют write(Uint8Array), TextDecoder(stream=true), без добавления фиктивных переводов строк. Вывод объединяется до 2048 символов и сбрасывается при input/завершении/ошибке. Traceback настоящего Python содержит playground.py и номер строки; dedent:false сохраняет исходные отступы. Избыточный вывод прекращает запуск и вызывает восстановление Worker.

При доступных WebAssembly.Suspending/promising input заменяется в builtins конкретного namespace на функцию, ожидающую Promise через pyodide.ffi.run_sync. Программа остаётся обычной синхронной Python-программой. UI показывает prompt, принимает строку или EOF, возобновляет Worker. Общий бюджет вычисления при ожидании приостанавливается; ожидание ограничено 2 минутами. Префикс prompt показывается отдельным полем ввода.

Без JSPI (или при выключенном интерактивном режиме) setStdin читает предварительные строки. Исчерпание вызывает EOFError. Поддержка отсутствие API проверяется удалением свойств, не присваиванием undefined: upstream определяет поддержку по наличию имени.

## Остановка и редактор

10 секунд вычисления по умолчанию (для будущего задания 100…30000 мс), ручной stop, предел вывода 65536 символов. Worker.terminate вызывается фреймом, старый фрейм удаляется; React создаёт новый runner и снова загружает локальный runtime. Следующий запуск независим от остановленной программы. Ошибки/timeout не записываются в учебный банк ошибок.

Textarea моноширинный, wrap=off, собственная горизонтальная/вертикальная прокрутка, font-size 16px. Tab вставляет 4 пробела, Shift+Tab убирает отступ; Enter сохраняет текущий и увеличивает после конечного :. Небольшие кнопки для отступов, скобок и кавычек помогают мобильному вводу. Сложного форматирования/IDE нет.

## Хранилище и backup

ege-python-playground, IndexedDB v1, drafts/current: schemaVersion 1/code/stdin/updatedAt. Каждое изменение ставится в последовательную очередь записи. Непрочитанный/повреждённый существующий draft автоматически не заменяется. UI сообщает сохранение/ошибку и предупреждает о незавершённой записи при закрытии. Один текущий draft; storage API можно расширить отдельными snippets позже.

Учебная IndexedDB ege-local-center, schema 2, sessions/exposures не менялись. Backup по-прежнему v2; старые v1/v2 читаются. Добавлена строгая необязательная валидация Question.python для будущих типов; нынешний банк этим не изменён. Python draft не включён в JSON-backup прогресса и не заменяется его импортом. Истории запусков/библиотеки программ нет.

## Будущие задания и проверка

PythonTask: type, starterCode, stdin, expectedOutput, timeout, visibleTests/hiddenTests, functionName, expectedReturn. Валидация ограничивает размер, JSON-тип значений и имена функций. Встроенные 67 вопросов не переоборудованы в программные задачи.

gradePython / runPythonCheck используют тот же PythonRunner. Для теста функции передаются только functionName и args; expectedOutput/expectedReturn/assertions/код тестов остаются снаружи, сопоставляются в assessment.ts. Каждый случай имеет новый Worker. Проверены stdout print(2+3), double(2)/double(-3), неправильная функция. Эти примеры есть только в тестах.

Невозможно скрыть публичные клиентские expected values от владельца браузера: будущие hidden tests означают отсутствие подсказки в учебном UI, а не криптографическую секретность. Пользовательской Python-программе ожидаемые ответы/код проверки напрямую не предоставляются.
